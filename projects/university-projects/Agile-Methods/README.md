# Scrum & Kanban Project Management with Trello

## 📚 Academic Project - Agile Methods

This project was developed as the final assignment for the **Agile Methods** course at UniFECAF. The objective was to act as a Product Owner managing a mobile application development project using Scrum and Kanban frameworks with Trello as the primary management tool.

---

## 🎯 Project Challenge

### Scenario

Working as a Product Owner at a technology startup that develops mobile applications for different sectors, I was assigned to manage the development of a new version of the company's flagship application. The development team consists of 5 developers, and the challenge was to coordinate all activities, deadlines, and tasks using agile frameworks Scrum and Kanban, with Trello as the management tool.

### Project Context

- **Who:** Mobile app development startup with a team of 5 developers
- **What:** Manage the development of a new app version, coordinating all activities, deadlines and tasks with Scrum and Kanban using Trello
- **When:** 3-month deadline with partial deliveries every Sprint (2 weeks per Sprint)
- **Where:** Fully remote project management using digital tools
- **Why:** The company needs to launch the new version to increase customer retention and attract new users with innovative features

### Main Challenge

As the project manager, I had to ensure the team follows the agile workflow, quickly identifies and resolves impediments, maintains focus on incremental deliveries, and ensures the final product meets customer and company expectations.

The primary challenge was to plan the project, balancing Scrum demands (incremental deliveries and constant team interaction) with Kanban workflow visualization. I was responsible for organizing the Product Backlog in Trello and ensuring tasks flow properly between lists: Sprint Backlog, In Progress, Testing, and Done.

---

## 🛠️ Frameworks & Tools Used

### Scrum Framework
- **Sprints:** 2-week iterations (6 sprints total over 3 months)
- **Ceremonies:** Sprint Planning, Daily Scrum, Sprint Review, Retrospective
- **Artifacts:** Product Backlog, Sprint Backlog, Increment
- **Role:** Product Owner (project manager)

### Kanban Methodology
- **Visual Board:** Workflow visualization in Trello
- **WIP Limits:** Work-in-progress limits to optimize flow
- **Pull System:** Team pulls tasks based on capacity
- **Flow Metrics:** Lead time and cycle time tracking

### Trello as Management Tool
- **Lists:** Product Backlog → Sprint Backlog → In Progress → In Testing → Done
- **Cards:** User stories and tasks with detailed information
- **Labels:** Categorization by priority and technical area
- **Checklists:** Technical subtasks breakdown
- **Due Dates:** Sprint deadlines and delivery dates
- **Comments:** Team collaboration and decisions tracking

✅ **Tier Progression:** Bronze → Silver → Gold → Platinum → Diamond

✅ **WooCommerce Integration:** Automatic coupon validation at checkout  
✅ **Mobile Notifications:** Push notifications for earned coins  
✅ **Offline Support:** Data synchronization when reconnected

## 💡 Lessons Learned

### What Worked Well

**Hybrid Approach:**  
Combining Scrum's structured ceremonies with Kanban's visual workflow provided the best of both worlds - predictability and flexibility.

**Trello as Central Hub:**  
Using Trello as the single source of truth improved transparency and reduced communication overhead.

**Regular Retrospectives:**  
Sprint retrospectives led to continuous improvements in team velocity and quality.

**Clear Definition of Done:**  
Establishing and maintaining DoD prevented technical debt and rework.

### Challenges Overcome

**Remote Communication:**  
Implemented strict rules for Daily Scrums and response times to maintain async communication discipline.

**Technical Dependencies:**  
Used API mocks and contracts to prevent frontend from being blocked by backend development.

**Story Point Estimation:**  
Improved accuracy after Sprint 2 by using historical velocity data and Planning Poker.

**Integration Complexity:**  
Created unified API layer and webhook system to handle multi-platform synchronization.
